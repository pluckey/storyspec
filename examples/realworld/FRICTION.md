# storyspec friction log (RealWorld example)

Where storyspec helped or got in the way while building RealWorld in Python with storyspec 0.4. The numbering starts again from 1. The MCP gateway's log was the first.

Severity: **block** (couldn't go on without changing storyspec), **bend** (worked around it), **papercut**, **win**.

| # | When | Severity | What happened | Workaround | Fix in storyspec |
|---|---|---|---|---|---|
| 1 | setup | win | A Python project needed only `implementedBy:`, the pytest `verifies` hook and a JUnit `testCommand`. The local check worked on the first run, and the deployed tier recorded PROOF.json with no changes to storyspec. | n/a | n/a |
| 2 | tiers | win | One test proves a scenario in both tiers. A session-scoped `api` fixture is the app in-process (memory adapters) unless `STORYSPEC_TIER=deployed`, when it is the running server on Postgres. Tests that don't name a tier count for the tier whose command wrote the report, which made this free. | n/a | document the pattern in the adoption guide |
| 3 | conformance | win | The official RealWorld Hurl suite runs inside the deployed tier. Its JUnit is merged with pytest's, and since its tests name no scenario, any failure fails the trace (`failing-test`), shown by breaking one assertion on purpose. | (was `scripts/merge_junit.py`) | fixed: a tier's `report` (and `testReport`) can list several reports |
| 4 | conformance | papercut | Hurl's JUnit test cases carry no file attribute, so the finding says `(unknown file): "hurl/tags.hurl" fails`. | none | fixed: a test case with no file or class is reported by its name |
| 5 | ports | bend | The Ports table and the `contract-tests` rule only see TypeScript, so the storage contract (`tests/contracts`, memory and Postgres) isn't credited to any adapter, and nothing fails if it's deleted. | contract tests are ordinary tests, and their failures still fail the trace | per-adapter coverage from report names in any language: the parametrised ids already are the adapter paths (`app/adapters/postgres`) |
| 6 | spec | bend | The suite ran green the first time, but a scenario test (S-008.1) caught a flake the Hurl suite didn't. An edit within the same millisecond as publishing kept the same `updatedAt`, because times are shown to the millisecond. | `later()` steps at least 1 ms | n/a: a win for writing scenario tests beside a conformance suite |
| 7 | proof | papercut | PROOF.json records `-dirty` when the deployed tier runs before the commit. Recording proof means: commit, run the tier, then commit PROOF.json. | run the tier after committing | `trace --tier` could warn when the tree is dirty |
| 8 | guidance | papercut | `framework-sync` warned that AGENTS.md was missing in a fresh example. Right, but the TypeScript-shaped guidance (`story()`, `src/domain`) doesn't fit a Python project. | wrote the Python specifics under "This project" | language-aware guidance, or a short section for projects that aren't TypeScript |
| 9 | pytest hook | **evidence** | CI failed every test during setup (#10), and the trace said "✗ no test" for all 48 scenarios instead of "✗ fails". The documented `verifies` hook recorded the scenario from an autouse fixture, which never ran when setup failed, so the failures couldn't be tied to their scenarios. | none needed | fixed: the hook adds the scenario at collection time (`pytest_collection_modifyitems`), so a setup failure still names it (docs/adopting.md) |
| 10 | CI | papercut | Python 3.14 evaluates annotations lazily, which hid a 3.13 failure: `ArticleStore` has a method named `list`, and later annotations like `-> list[str]` in the class resolved to it. Local runs passed, and CI on 3.13 failed in setup. | `from __future__ import annotations` in the ports; CI runs the oldest supported Python (3.12) | n/a (not storyspec's) |
| 11 | schema | **evidence** | While adding report lists, the config schema turned out to have no `tiers` or `defaultProof` since 0.3. It sets `additionalProperties: false`, so editors flagged every config that used tiers, this one included. | none | fixed, with a self-hosted scenario (S-004.1) that keeps the schema equal to the config's settings |
| 12 | timestamps | **evidence** | Viewing seeded data against a local Postgres showed `createdAt` as `-05:00`, not `Z`: Postgres answers in its own zone, and CI's runs in UTC, so no test could see it. | none | fixed (S-006.5). The deployed tier's Postgres now runs in America/Chicago on purpose, so the scenario fails if it regresses |
| 13 | layers | **win** | storyspec 0.6 reads Python imports with ast-grep, so `layers` now enforces `app/`'s hexagonal layout. The existing code passed, and a planted `app/domain` → `app/adapters` import failed the trace. Adding the language was a data description in storyspec, not a plugin. | n/a | n/a |
| 14 | regeneration | **evidence** | A cleanroom TypeScript regeneration from the stories, the acceptance tests and Hurl alone passed everything in about 8 minutes, and made about 27 silent choices; at least 5 differed from this app (see `regenerations/`). That led to `### Decisions` in specs: each judgment call pinned by a scenario or marked free. | n/a | storyspec 0.7: the `decisions` rule and a Decisions table in TRACE.md |
| 15 | decisions | **evidence** | Pinning "tags are alphabetical" (S-014.2) failed at once on the deployed tier: Postgres sorts by its locale's collation, which ignores punctuation, and the memory adapter sorts by code point. The two adapters had disagreed all along, and only a pinned decision exposed it. | `ORDER BY tag COLLATE "C"`; a storage-contract check | n/a: a decision that sounds obvious ("alphabetical") still needs its precise meaning written down |
